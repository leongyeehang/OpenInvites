# 05: Create, publish, and view an event

**What to build:** A host creates an event, saves it as a draft, edits it, publishes it, and anyone with the event link sees a bare event page. A draft's link shows "this invitation isn't ready yet" to everyone but the host.

**Blocked by:** 02 Host accounts

**Status:** done

- [x] Event schema: UUIDv7 ids generated by Postgres (ADR-0004); a unique ten-character slug from a 62-character alphabet generated by a cryptographic random source; title; start instant; optional end; all-day flag; IANA time zone defaulting to the host's device zone; location as free text; description as plain text (rich text arrives in ticket 17); state Draft or Published; owning host.
- [x] Dashboard with Upcoming and Past sections; each card shows status, start time in the event's zone, and placeholder counts of zero; a New event action.
- [x] Create and edit form with validation (end after start, title required); saving produces a Draft; a Publish action moves it to Published; edits after publishing are reflected on the page immediately.
- [x] Hosts with SMTP configured must have a verified email to create an event; the create action explains why and offers to resend.
- [x] The event page at the link is server-rendered with title, "Hosted by" display name, when in the event's time zone, where, and description; it sends a noindex robots signal in both meta and header; nothing anywhere lists events.
- [x] A draft's link shows the "not ready yet" page to non-owners; the owner sees a preview with a Draft banner. An unknown slug shows a not-found page.
- [x] Browser tests: create, open the draft link in a fresh context and see "not ready", publish, see the page, edit and see the change. Unit tests: slug length, alphabet, and collision handling; time zone display.

## Comments

**2026-09-21, implementing agent.** Done. Lint, type check, 44 unit tests, and 42 browser tests (21 scenarios at 390px and desktop) pass locally against the production image on the Compose `test` profile.

How it landed:

- Events module in `src/events/`: `slug.ts` (ten characters from the 62-character alphabet, cryptographic source, retry on a taken slug), `time.ts` (wall-clock to instant in the event's zone with a round-trip check, formatting in the event's zone, when an event ends, the Upcoming/Past split), `form.ts` (the form's rules), `repository.ts`, and thin server actions. The `event` table has UUIDv7 ids and a unique slug (migration `0002_events`).
- Routes: `/dashboard` (Upcoming and Past, New event), `/events/new`, `/events/<id>` (link, publish, edit form), `/e/<slug>` (the event page; a draft shows "not ready" to anyone but its host, who sees a Draft banner). Unknown or malformed slugs are not found. Event pages send `X-Robots-Tag: noindex` from `next.config.ts` and a robots meta tag.
- All-day events store midnight in the event's zone with the flag set; the end of an all-day event is the next local midnight, correct across clock changes.
- The time zone select defaults to the host's device zone in the browser and offers UTC, which Node's list omits; the server accepts any zone Intl can format, including browser aliases such as Asia/Kolkata.
- Untranslated strings now fall back to English instead of showing raw keys (`src/locale/fallback.ts`), because the event page is guest-facing and Chinese translations are ticket 20.
- Review caught and fixed before commit: the slug collision check read Drizzle's wrapper instead of the Postgres error underneath; 30 February and times inside a DST gap passed validation; the manage page kept a stale title after saving.

Left for later tickets or noted:

- Viewer-zone line, countdown and map link (15); theme and Poster layout (06); RSVP counts (07); link reset and the retired-link page (14); rich text (17); cancel and delete (16).
- The New event page shows the explanation with a resend button while the layout's verification banner is also visible, so an unverified host sees two resend buttons on that page.
- Browser aliases the server list lacks are accepted but not canonicalised, so a host in Kolkata stores `Asia/Kolkata` while the list says `Asia/Calcutta`. Both format identically.
