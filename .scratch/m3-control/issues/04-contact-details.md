# 04: Contact details: email optional or required, and a phone number

**What to build:** The email field on the RSVP form becomes a choice, don't ask, optional or required, and a phone field joins it with the same choice. The guest list shows both. Phone numbers are asked for, not proven.

**Blocked by:** nothing (03 is not needed)

**Status:** done

- [x] Schema: enum `contact_field` (`none`, `optional`, `required`); `event.email_field contact_field not null default 'none'` replacing `ask_email` (the migration adds the column, sets `optional` where `ask_email` was true, then drops `ask_email`); `event.phone_field contact_field not null default 'none'`; `rsvp.phone text`. Migration 0026.
- [x] `src/rsvps/form.ts`: `CONTACT_FIELDS = ["none", "optional", "required"]`, `RsvpSettings` becomes `{ plusOnesAllowed; requirePlusOneNames; emailField; phoneField }`, `RsvpInput` gains `phone: string | null`, `RsvpFormError` gains `emailRequired`, `phoneRequired`, `phoneInvalid`; `isPhone(value)` (pure): 5 to 20 characters, each a digit, a space, `+`, `-`, `(`, `)` or `.`; the email is read when `emailField` is not `none` and required when `required`, the phone likewise; both stored trimmed, never formatted. The contact fields are asked wherever the email is asked today, for the same statuses.
- [x] Event form: the "Ask guests for an email address" checkbox becomes a **Contact details** group: "Email" (`NativeSelect`: Don't ask, Optional, Required) and "Phone number" (the same three). The reminders hint ("Guests get email only if you ask…") shows when Email is Don't ask. `EventInput`, `EventFormFields`, `parseEventForm`, `fields()` in `src/events/actions.ts`, and `duplicateInput` carry both fields. Keys under `Events.form.contact.*`.
- [x] The flow (`use-rsvp-flow.ts` and the three layouts): the email field is marked required when the host requires it and `emailRequired` maps to its step; the phone field sits beside it with the same optional or required behaviour, `inputmode="tel"`, `autocomplete="tel"`, and `phoneRequired` and `phoneInvalid` ("Enter a phone number of 5 to 20 digits.") map to it; the confirmation shows the phone as it shows the email ("We'll reach you at {email}" gains a line "Phone: {phone}" when given). Thread asks for the phone as a text turn after the email. Keys under `Rsvp.*`.
- [x] Host guest list: `HostGuest` gains `phone`; `GuestRow` shows it under the email; the host's edit form (`parseHostEdit`, `editRsvpAsHost`) can set the email and the phone.
- [x] `e2e/events.ts`: `DraftFields.askEmail` selects Email "Optional"; new `email?: "optional" | "required"` and `phone?: "optional" | "required"` select the matching choice.
- [x] Unit tests: `isPhone` (4 and 21 characters, letters, `+65 9123 4567`, `(02) 555-1234`); `parseRsvpForm` with email and phone in each of none, optional and required, blank and given.
- [x] Browser tests (`e2e/contact-details.spec.ts`): an event with Email required refuses a blank email with the line at the right step and accepts a filled one; Phone optional shows the field, a number given appears on the host's guest list; Phone required refuses blank; `12` is refused as invalid; Email Don't ask shows no field; the host edits a guest's phone and it shows; one case each in Broadsheet and Thread (email required, refused blank then accepted). At both widths.

## Notes for the implementer

- `askEmail` is read in `src/rsvps/form.ts`, the event form, `duplicate.ts`, the reminders hint, `e2e/events.ts` and the browser specs that set it; the type checker finds the rest once `RsvpSettings` changes.
- The stop-mail page and every mail rule are unchanged: a phone is shown to the host and used for nothing else.
- Commit subject, e.g. `RSVP form: a host can require a guest's email and ask for a phone number`.
