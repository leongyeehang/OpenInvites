# 09: Turnstile

**What to build:** When the operator sets Cloudflare Turnstile's keys, the widget guards the email sign-up form, the RSVP form in every layout, and the report form; the server verifies each token before the action does anything else. Without keys nothing changes.

**Blocked by:** 05 The email proven by a code (the first submit of a reply is the gated one), 02 Report an event

**Status:** done

- [x] `src/turnstile/config.ts` (pure, unit tested): `turnstileConfigFromEnv(env)` returns `{ siteKey, secretKey }` when both `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` are set, null when neither, and throws "TURNSTILE_SITE_KEY and TURNSTILE_SECRET_KEY must be set together" when one is; `isTurnstileConfigured()`, `turnstileSiteKey()`. `instrumentation.ts` calls it among the start checks.
- [x] `src/turnstile/verify.ts`: `turnstileVerdict(json: unknown): "ok" | "failed"` (pure: `success === true`), and `verifyTurnstile(token: string | null, remoteIp: string | undefined): Promise<"ok" | "failed">` posting `secret`, `response` and `remoteip` form-encoded to `https://challenges.cloudflare.com/turnstile/v0/siteverify` with a five-second timeout; a missing token, a network failure or a non-JSON answer is `failed` and logged once with the reason. The client's address is the one the rate limits believe (`clientKey`'s resolution of `X-Forwarded-For` with `TRUSTED_PROXY_HOPS`).
- [x] `src/turnstile/turnstile.tsx`, a client component rendered only when configured: loads `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit` once per page, renders the widget in managed mode with the viewer's locale and `theme: "auto"`, writes the token into a hidden `cf-turnstile-response` input inside its form, disables the form's submit (`disabled`, with the accessible name unchanged) until a token is present, and when the script fails to load shows `Turnstile.unavailable`: "The check couldn't load. Turn off your ad blocker for this page and try again." The widget has an accessible label "Bot check".
- [x] Gated forms: the email sign-up form (the server action verifies before calling Better Auth's sign-up; the Google and GitHub buttons and the sign-in page are not gated); the RSVP form in every layout (the hook sends the token with the first submit that reaches the server for a reply, the one that saves it or sends the code; the code submit and "Send it again" are not gated; `saveRsvpAction` verifies after the rate limit and before anything else); the report form. A failed verification is refused with `checkFailed`: "Please complete the check and try again." in each form's error vocabulary, and the form can be sent again (the widget resets).
- [x] Compose: `app-social` gets `TURNSTILE_SITE_KEY: 1x00000000000000000000AA` and `TURNSTILE_SECRET_KEY: 1x0000000000000000000000000000000AA` (Cloudflare's published always-pass test keys), with a comment; `.env.development` lists both unset with a comment; `deploy/.env.example` documents both.
