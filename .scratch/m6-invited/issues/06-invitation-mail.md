How it landed:
- The mail, in `event.locale`: "Hi {name}," then "{host} invited you to {title}.", the letter as written (its own paragraph, only when there is one), "When:" (`formatWhen` in the event's zone and language) and "Where:" each only when known (a published event with an open date poll has no date), "Open your invitation: {link}", and on an invite-only event "When you open it, you’ll be asked for a code, which is sent to this address." The footer is `Mail.invitationFooter`: "You’re getting this because the host of {title} invited you at this address. To stop emails about this event: {url}". `{host}` is the signed-in host who presses Send (a co-host sending invites is the one inviting), not the event's owner.
- `invitationMail` takes the invite's `token` as well as `name` and `letter`, as the link is built from it.
- `markInvitesSent(eventId, ids, now, { unsentOnly }, db)` is one `UPDATE`: `mail_token = coalesce(mail_token, case id when … then <fresh token> … end)`, so each row gets a token of its own the first time (one literal for every row would break the unique index) and keeps it after, and Send again carries the same stop link. It marks only rows with an email and no `mail_stopped_at`; with `unsentOnly` (the "everyone" path) only rows with `sent_at` null, so two "Send to everyone" at once mail nobody twice: Postgres re-checks the condition on rows the first has locked. A single statement is its own transaction, so the actions call it without one; the `db` parameter is there for a caller that has one.
- Both actions: the host and `can(role, "guests")`, then `isMailConfigured()` (else `errors.noMail`), then **the event must be published** (else `Invites.sendWhenPublished`, see below), then one `consume("mail", headers)`, then mark, then `queueGuestMail(…, "Mail.invitationFooter")`, which queues and does `after(kickMailWorker)`. "Everyone" lists the unsent first and, when there is nobody, answers `sentCount` 0 without consuming. As with announcements, the mark comes before the queue and a failure to queue is logged, not reported: such a row would read Sent with no mail, and Send again mends it.
- The stop link: `stopInviteMail` sets `mail_stopped_at` (`coalesce`, so the first time is kept) and keeps the email. `/m/[token]` is unchanged: for an invite it shows the email and Stop, also after stopping (pressing again changes nothing and says Done again).
- The page: Send (aria "Send the invitation to {name}") on rows with an email and no stop, on a published event with mail; once sent "Sent {date}" (`formatMoment`, event zone, host's language) and the button reads "Send again" ("…to {name} again"). "Send to everyone not yet sent ({count})" sits above the list whenever any invite can be mailed, and stays at (0), disabled, after use so its "Sent N invitations." stays visible. The "Stopped email" badge sits beside the state badge. What a Send did is said at the end of that row's buttons.
- Share: shown beside Copy when the browser has `navigator.share` (as on the share page), with `{ title: event title, text: Mail.invitation.subject in the event's language, url: the invite link }`; without a share sheet there is only Copy. Like Copy, it goes once the guest has replied through the invite (the link is then their edit link).
