How it landed:
- `isDay` and `TIME` are exported from `src/polls/poll.ts` rather than lifted; `schedule.ts` imports them by a relative path, as everything `schema.ts` loads does.
- `parseSchedule` names a row by its place in the sheet as posted, blank rows counted, so "Item 3" is the third row the host sees even when a blank one sits above it. The time is cut to minutes as the poll's is (a time field may give seconds). Every row is checked before any is sorted, so a refusal is about the row as typed, not where it would land.
- `parseScheduleRefresh` answers `undefined` for anything but the two settings, and the action refuses that as `scheduleInvalid`. The action takes `{ items: unknown; refresh: unknown }`, since a server action's arguments are posted.
- The sheet's rows live in a form remade each time the sheet opens, so it starts from the schedule as saved (in order) and a refused edit closed with Escape is forgotten. It opens with no rows when there is no schedule: a row starts on the event's day, so a blank first row would refuse an empty Done. Title, place and note carry `maxLength`, so the length refusals are for crafted posts.
- Row labels carry the row's number, as the poll's do ("Day 2", "Start time 2", "End time 2 (optional)", "Title 2", "Place 2 (optional)", "Note 2 (optional)"), and the refusals read "Item {n} …", as "Remove item {n}" does. Apostrophes are typographic (’), as everywhere else in the messages.
- `duplicate.test.ts`'s whole-`Event` fixture gains `scheduleRefresh`, which is also in its list of what a copy does not take.
