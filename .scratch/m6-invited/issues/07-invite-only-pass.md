# 07: Invites: an invite-only event opens only to a device with a pass

**What to build:** The gate: on an invite-only event, the page and everything that opens an event by its slug open only to a host or to a device with a pass; the locked page lets an invitee prove their email with a code; a device with a pass has the invite as its identity. The setting itself is not yet offered to hosts (ticket 08 adds the switch and what turning it on does); this ticket's browser tests set `invite_only` through the repository or a test-only path, or wait for 08's switch, whichever the implementer finds honest, and say which.

**Blocked by:** 05 A phone, a letter and a pasted list for each guest

**Status:** ready-for-agent

- [ ] **Identity by id, not token** (prepares 08). Today `findInvitedRsvpOnThisDevice` finds the reply by the invite's token (`src/invites/device.ts:41–46`), `guestRsvp` builds `/i/<token>` whenever `rsvp.inviteId` (`src/rsvps/guest.ts:55`), and `/i/[token]` sets `rsvp_` to the invite token for an answered invite (`src/app/i/[token]/route.ts:23`). A reply made before the switch keeps its own edit token, so none of these would find it. Change: `findInvitedRsvpOnThisDevice` loads the reply by `invite.rsvp_id`; `/i/[token]` always sets `invite_` (never `rsvp_`); `MyRsvp` gains `inviteToken: string | null`, filled on both lookup paths (the `rsvp_` path loads the invite when `rsvp.inviteId`); `guestRsvp` uses `inviteUrl(inviteToken)` when present; `saveRsvp` keeps using the invite token as a **new** reply's edit token (`src/rsvps/repository.ts:223`). `inviteCookieOptions` (`device.ts:15–17`) becomes a year: the cookie now stands for a reply.
- [ ] `src/invites/pass.ts` (pure): `passCookieName(eventId)` = `pass_${eventId}`; `PASS_DAYS = 365`; `signPass({ eventId, inviteId, expiresAt }, secret)` → `inviteId.expiresMs.hmac` (`node:crypto` HMAC-SHA256 over `eventId:inviteId:expires`); `readPass(value, eventId, secret, now)` → `{ inviteId }` or undefined, compared with `timingSafeEqual`.
- [ ] `src/invites/access.ts` (pure): `admitted({ pass, invite })`: true with a valid pass; else true only when the device's invite (the `invite_` cookie, or the reply's `invite_id`) exists and **has no email**; false otherwise. An invite with an email is admitted by a pass alone, never by its link or the reply's edit link (spec, "Who is in").
- [ ] `src/events/access.ts:8`: `eventPageFor(event: { state; inviteOnly }, viewer: { isHost; admitted })` → `"invitation" | "notReady" | "locked"`: a draft → notReady for non-hosts first, then the lock, then invitation (a cancelled invite-only event shows its notice only to those in).
