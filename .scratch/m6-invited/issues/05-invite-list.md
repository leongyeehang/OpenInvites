How it landed:
- `parseLetter` turns each `\r\n` into `\n` before trimming and measuring: a browser posts a textarea's line breaks as two characters while the field (and its `maxLength`) counted one, so a 1000-character letter with line breaks would otherwise be refused. Length is `String.length`, as `MAX_NAME` is measured; a Chinese character counts once.
- `parseInviteLines` splits on line breaks (CRLF too), skips blank lines, numbers lines as the host sees them (blank ones counted), splits each line at its first two commas and gives anything after the second comma to the phone, where it is refused as one. A list with nobody on it is refused as line 1, `nameRequired` (the textarea is `required`, so only a hand-made post meets it). The first bad line is named as `Invites.errors.line` ("Line {line}: {error}") wrapping the field's own error.
- `createInvites` locks the event row, counts, and inserts the whole list in one statement or returns null when `made + inputs.length` passes 500; the action then says `errors.tooManyAtOnce`. The list is newest first as before, so a pasted list shows its last line first (one insert, one `created_at`, `uuidv7` ids in line order).
- `createInviteAction` reads the letter only while the event has letters on (the form offers it only then). `saveLetterAction` saves on or off, so a stale page loses nothing; an empty letter takes it away. A letter for an invite deleted meanwhile is refused with `errors.notFound`.
- `setLettersEnabledAction(eventId, on)` takes `on === true` (a server action's arguments are the client's) and moves `updatedAt`. The switch is the host area's `Checkbox` ("Personal letters", its hint below), saved on change in a transition with `useOptimistic`; the page is redrawn with the letter fields shown or hidden. Letters are kept while letters are off.
- `lettersEnabled` stays off `EventInput` and the Settings sheet; `inviteOnly` is a column, `createEvent`'s input (`NewEvent = MaybeDated<EventChanges> & Partial<Pick<Event, "lettersEnabled" | "inviteOnly">>`) and `duplicateInput` only.
- Each row's letter field and its button are named with the guest's name through `aria-labelledby` (the visible label or button text, then the row's name: "Letter Mei Lin", "Save letter Mei Lin"), with no new keys; the add form's field is plainly "Letter". The phone input is `inputMode="tel"`, not `type="tel"`, as the email is not `type="email"`. `MAX_LETTER` reaches the client fields as a prop: `invite.ts` imports `node:crypto` through the token and cannot go into a client bundle.
- The prefill: `Invited` gains `phone`; the page passes the invite's phone only when `phoneField` is not `none` (a voter has none), and `draftFrom` starts a first answer from it.
