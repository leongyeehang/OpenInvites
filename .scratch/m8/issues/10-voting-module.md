# 10: Voting: the album vote is a module of its own, and the host starts, closes, reopens and turns it off

**What to build:** The album vote lives in `src/voting/`, with one public entry, and touches the app only through its named hooks. An event's album vote is off, open or closed. The host starts it, closes it, reopens it and turns it off from a Voting block in the editor's Settings, below the album's own block; turning it off deletes its votes after a confirmation that gives their number, and closing and reopening keep them. Every rule the later voting tickets draw on (who may vote and for what, places with ties, the tie-break's places, what is shown to whom, the shuffle) is written here as a pure function and unit-tested. A duplicated event copies the awards and the voting settings and starts with voting off.

**Blocked by:** 01 (the feature switches and the module rule); it runs after 09 in the plan's order and takes the next migration number

**Status:** done

## Notes for the implementer

- **(plan)** Voting imports nothing from `src/album`: ticket 01 caps the album's outside dependents and this module must not add one. `albumOpenTo` restates `albumState(...) === "open" && albumView(...) === "open"` for the module's actions; the event page passes the album's own answer as `view`. The unit cases mirror `visibility.test.ts` so the two cannot drift unseen; M9's album entry replaces the restatement. Voting reads album items only as `photo` rows through `@/db/schema` (id, event, kind, status, owner), never through album code.
- **(plan)** All the module's client components read under the one namespace `Voting`, and every page that imports `@/voting` passes `"Voting"`: `client-messages.test.ts` walks a page into everything the entry re-exports. Wording used only on the server (the announcement drafts, tickets 14 and 16) lives in `VotingDrafts`, which is never passed.
- **(plan)** The walk stops at a `"use server"` module because a client component holds only a reference to an action, and an action renders nothing; otherwise `src/events/actions.ts`, imported by the Duplicate and Delete buttons, would make every page with them send the Voting messages.
- **(plan)** The default award is made when it is first needed: an event has no `album_award` row until a host starts a vote or changes an award (ticket 13), under the event's lock; until then the block and the album treat `DEFAULT_AWARD` as the one award.
- **(plan)** Reopening ends any tie-break and deletes its votes: the first round's places may change once guests vote again, so an earlier tie-break would order the wrong items. Starting and reopening clear a closing time that has passed, or the vote would read closed at once.
- **(plan)** The shared rule `countsShown` takes the award's stage rather than the event's state, because a tie-break hides its counts from guests while the event's vote is closed.
- No client component outside `src/voting` imports `@/voting` except with `import type`: the entry carries the repository.
- No type named `Voter` (the date poll's word, `CONTEXT.md`); "album vote", "award", "tie-break" in code and comments.

How it landed:
- Ruling: `mayVote` also answers false while the album itself is shut (a draft, a cancelled event, before the start), restating `albumState`, so a cancelled event's vote takes nothing even if the page passed `view: "open"`. One unit case covers it. Cost if wrong: one condition.
- Ruling: `startVoting` acts only from `off`; a press on an open or closed vote leaves it as it is (reopening is `reopenVoting`'s, which ends a tie-break). It returns `{ error?: "albumNotOpen" }`, which the action passes on. `reopenVoting` reopens a vote that reads closed by its time too (`votingState`, not the stored value). `turnOffVoting` keeps the closing time, a setting; starting again clears it only if it has passed.
- Ruling: `VotingSettings` does not load `listAwards`: this ticket's block shows no award, and an unused read would fail lint. Ticket 13 adds it with the award list.
- `finalPlaces` takes the tied items from `tiedForFirst(before)`, not from the award's `finalists`, so `awardPlaces` folds rounds with nothing but the votes; ticket 15 should set `finalists` to `tiedForFirst(awardPlaces(...))` when it opens a round, which keeps the two equal.
- `shuffledFor` is FNV-1a with a final mix over `${viewerKey}:${id}`, ties by id.
- The block's Turn off confirmation is the `EmptyAlbumDialog` pattern (a form in the `AlertDialog`, closed after the save).
