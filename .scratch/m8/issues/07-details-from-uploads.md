# 07: Album: an open item shows its technical line, and the host may keep when and with what it was taken

**What to build:** Under an open item the viewer shows a line of technical facts: for a video its size, frame rate, HDR, length and file size; for a photo its size in pixels and file size. Two switches in the host's Album settings, both off by default, keep the capture date and time, and the camera with its lens and exposure. What a switch keeps is read while the item is processed and stored on the item in the database; the stored files keep nothing, as in M7, so a download never carries a detail. With capture time kept, the host may order the album by when items were taken, falling back to when they were added. Location is never read. A detail read under a switch that is later turned off stops being shown and is not erased.

## Notes for the implementer

- **(plan)** No EXIF library is added. `sharp`'s `metadata()` hands back the raw EXIF block and no tags (`exif?: Buffer`), so it is not enough; a reader of the TIFF structure in `src/album/exif.ts` that reads IFD0 and the Exif IFD by the tags named, bounds-checked and never following the GPS pointer, makes "location is never read" true by construction and needs no ADR.
- **(plan)** A capture time with no offset is read in the event's zone (`toInstant`), where the party was; one before 2000 or more than a day after processing is dropped (zeroed clocks, 1970).
- **(plan)** The two switches and the order are fields of the Settings sheet's form, unlike the album reminder (M7 plan ruling 9): nothing on any other page changes them, so posting every field on every change keeps them right. The order's select is never disabled, since a disabled control is not posted; "When taken" applies only while capture time is kept.
- **(plan)** A photo's size in the line is the picture as added (`details.pixels`, written for every photo since it is the picture's, as `fps` is), not the 2048-pixel copy the viewer shows; the file size is the item's size as uploaded (`photo.bytes`), what storage counts.
- ADR-0008 and the plan: no file outside `src/album` that does not import it today starts to; `src/events/form.ts` and `settings-sheet.tsx` already do. A detail whose switch is off is left out by `albumFor` on the server, never hidden in the browser.
