# 01: Features: the operator switches the album, videos and voting on or off, and new features live apart

**What to build:** A feature list in `src/features/` names the site's optional features (Album, Videos, Voting), what each needs, and whether the site has it on. A Features card on Site settings lets the operator switch each on or off for every event. With the album off, hosts and guests are not shown it and its actions refuse; with videos off, albums take photos only and the videos they hold still play. Nothing is deleted. ADR-0008 records the rules every later ticket follows, and a lint rule enforces them for the new folders.

## Notes for the implementer

- Pure modules take the switch as a boolean (`albumOn`, `videosOn`); the callers, which are server code, read `siteFeatures()` and call `featureOn`. This keeps `album.ts` and `video.ts` free of database imports, and keeps `@/features`, which carries the repository, out of client bundles **(plan)**.
- Switches are rows of their own table rather than columns on `instance_settings`, so a feature added later brings its switch without touching the settings row **(plan)**.
- **(plan)** The spec counts 24 outside dependents of the album; the command above prints 25 on 2026-11-11, because `src/instrumentation.ts` imports `./album/ffmpeg` and `./album/queue` dynamically. The ADR records 25 and the test guards it. A ticket that must add a dependent moves album code inside `src/album` instead, or records a ruling that raises the number in both places.
- Voting has no code yet: its switch is stored and shown now, and ticket 10 reads it with `featureOn(switches, "voting")` and adds its scenarios to `e2e/features.spec.ts`.
- The Storage card's "Process videos for playback" switch is unchanged; it is not a feature switch.
