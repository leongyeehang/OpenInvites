# 13: Voting: the host names the awards, each for photos, videos or both, and guests vote in each

**What to build:** A vote has one award or more, at most eight. A new vote starts with Favourite, for photos and videos. In the Voting block the host adds awards from suggestions (Best photo, Best video, Funniest, Best group shot) or by name, renames them, puts them in order with Move up and Move down, says what each is for, and removes one after a confirmation that names how many votes go with it. On the event page, an award picker switches between the awards and shows where the viewer has voted; while an award for photos only or videos only is chosen, the album shows only those items, for voting and for its results, with nothing dimmed. Each person has one vote in each award. A duplicated event keeps its awards.

## Notes for the implementer

- **(plan)** A scope may change while an award has votes. Votes for items it no longer shows are kept, not counted, and not shown as the voter's; that voter may vote again, which replaces the hidden vote. Changing the scope back restores them. Deleting them would make a slip of the select cost guests their votes.
- **(plan)** At most eight awards: the picker must stay one row of pills on a phone, and every award is one more vote for each guest. At least one, since a vote with no award has nothing to vote in.
- **(plan)** A suggestion is stored as words in the language of the host who chose it, as any name they type is; a guest reading another language sees the host's words.
- An award's display name comes from the server (`Voting.favourite` for a null name), so the client never needs the default's key.
- A live photo (ticket 08) is a photo for every scope.
