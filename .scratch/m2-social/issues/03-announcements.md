# 03: Announcements, and "send a reminder now"

**What to build:** A host posts an announcement that appears on the event page and is emailed to the guests they choose by status. An announcements page under the event lists them and deletes one. A "Send a reminder now" button drafts a reminder as an announcement.

**Blocked by:** 02 Cancellation notice and stop emails

**Status:** done

- [x] Schema: `announcement` (id, `event_id` cascade, `body` text, `audience` rsvp_status[] not null, `created_at`). At most ten per event, checked in the module, refused with a message on the form.
- [x] `src/announcements/`: `announcement.ts` (parse the form: body 1 to 2000 characters, line breaks kept, trimmed; audience a non-empty subset of Going, Maybe, Can't go; the ten cap), `audience.ts` (`recipients(rsvps, audience)`: the guests with an email whose status is in the audience, pure, unit tested), `repository.ts`, `actions.ts`.
- [x] `/events/[id]/announcements`: a page reached from the manage page's buttons row ("Announcements"), with the form (textarea, three checkboxes defaulting to Going and Maybe, "Send") above the list, newest first, each with its date and "Sent to Going and Maybe" (the audience in words), and a Delete button with confirmation. The page explains: "Everyone who opens the event link can read announcements on the page. The email goes to the guests you pick who gave an email." When `askEmail` is off it adds: "Guests get email only if you ask for their email on the RSVP form."
- [x] Sending queues one `guestMail` per recipient (`Mail.announcement`: subject "{title}: a message from the host", body is the host's text as written, then the footer), kicks the worker, and counts once against the `mail` rate limit. Without mail the announcement is still posted to the page and the form says no email was sent.
- [x] The event page shows announcements in a section headed "From the host" (`EventPage.announcements`), newest first, each with its date in the viewer's locale, on the invitation (not the not-ready page), for every viewer. A cancelled event keeps them. Line breaks are kept; nothing else is formatted. The Poster layout places it after the description card.
- [x] "Send a reminder now" on the announcements page fills the form (client side) with `Announcements.reminderDraft` in the host's language: the title, the date and time in the event's zone (all-day events: the date), the location when there is one, and the event link. The host edits or not, then sends it as any announcement.
- [x] Unit tests: `recipients`; the form parser's limits (empty, 2000, 2001, empty audience, unknown status); the ten cap.
- [x] Browser tests (`e2e/announcements.spec.ts`): three guests with emails, one per status; the host sends to Going only; Mailpit shows one mail to the Going guest with the host's text and the footer and none to the others; the announcement shows on the event page for a guest who has not replied; the host deletes it and it is gone from the page; "Send a reminder now" fills the form with the title and the link; the eleventh announcement is refused.

How it landed:
- **Schema** (`drizzle/0016_announcements.sql`): `announcement` (id, `event_id` not null, cascade, `body` text, `audience` `rsvp_status[]` not null, `created_at`), with `announcement_event_id_idx` like every other event foreign key. No existing rows to fill.
- **`src/announcements/announcement.ts`**: `parseAnnouncement({ body, audience })` turns CR LF (which a browser posts for a textarea's line breaks) into one line feed, trims, then requires 1 to 2000 characters (`bodyRequired`, `bodyTooLong`). The audience must be non-empty (`audienceRequired`) and every entry one of `going`, `maybe`, `cant` (`audienceInvalid`). It is kept as the set the host ticked, each status once, in the RSVP buttons' order. `roomForAnother(posted)` is the ten cap (`MAX_ANNOUNCEMENTS`). `DEFAULT_AUDIENCE` is Going and Maybe.
- **`src/announcements/audience.ts`**: `recipients(rsvps, audience)` keeps the RSVPs whose status the audience names (`audience.includes(status)`, never by exclusion) and that have an email and a mail token, in the order given, typed so `email` and `mailToken` are strings.
- **`src/announcements/repository.ts`**: `listAnnouncements(eventId)`, newest first (`created_at desc, id desc`). `createAnnouncement(eventId, input)` takes the event row `FOR NO KEY UPDATE`, counts the event's announcements and asks `roomForAnother`, all in one transaction, so two posts at once cannot both take the tenth place. It returns null when the event is full. `NO KEY UPDATE` does not block guests' RSVP inserts, whose foreign key takes `KEY SHARE`. `deleteAnnouncement(eventId, id)` is scoped to the event.
- **`src/announcements/actions.ts`**: `postAnnouncementAction(eventId, state, formData)` runs `requireHost` and `findHostEvent`, then parses. With mail, it reads `listMailableRsvps` and applies `recipients`. When that leaves at least one guest, it calls `consume("mail", headers)`; a refusal answers `errors.tooFast` before anything is written. Then it creates the announcement (full: `errors.tooMany`) and queues one `guestMail` per recipient, the subject `Mail.announcement.subject` in the guest's locale and the body the host's text. Then `after(kickMailWorker)`. Queuing is wrapped like `notifyGuestsOfCancellation`: a failure logs `Mail: could not queue the guests' email about an announcement to event <id>` and the post stands. The answer is `sent` ("Posted to the event page and emailed to # guests", or for none "None of the guests you picked gave an email, so nobody was emailed") or, without mail, `postedNoMail` ("Posted to the event page. No email was sent."). `deleteAnnouncementAction(eventId, id)` checks the host's event and `isUuid(id)`.
- **`/events/[id]/announcements`** (`page.tsx`, `announcement-form.tsx`): the back link, the heading, the explainer, the `askEmail` hint when the event does not ask for email, and the no-mail line when the instance has none. Then the form, then the list. Each list item shows the time (`formatMoment`, in the event's zone, as on the guest list), "Sent to …" built with next-intl's `format.list` over the status words, the body with its line breaks, and Delete in an `AlertDialog` ("Delete this announcement?", "Delete it", "Never mind"), the way the share page confirms a reset. The form's text and boxes are React state, so a refusal keeps them, and they reset after a successful post. "Send a reminder now" fills the text with `Announcements.reminderDraft`, which the page renders on the server in the host's language: the title, `formatWhen(event, locale)` (the event's zone; the date alone for an all-day event), "Where: …" only when there is a location (an ICU `select` on `located`), and the event link.
- **Manage page**: "Announcements" after "Share" in the buttons row. **Proxy**: `notFoundHere`'s `/events/` pattern has `/announcements`, so another host's event, or `/events/new/announcements`, gets the whole not-found page with 404. `e2e/events.spec.ts`'s "mistyped" test now covers both paths.
- **Event page**: `listAnnouncements` loads beside questions and the upload. `PosterLayout` takes `announcements` (id, body, createdAt) and draws a Glass card after the description card: `SectionLabel` "From the host", then an `<ol>` with each item's time (`formatMoment`, the event's zone, the viewer's locale) and its body (`whitespace-pre-line`, `break-words`). The not-ready page returns before the layout, so a draft shows guests nothing. A cancelled event keeps them.
- **Messages**: `Mail.announcement.subject`, `Events.manage.announcements`, `EventPage.announcements`, and an `Announcements` namespace (the page, the form, the list, the errors, the reminder). All are in `en.json`, `zh-Hans.json` and `zh-Hant.json`. The page passes `["Announcements"]` to its client form.
- **Docs**: `docs/operator/configuration.md`'s Mail paragraph and the `RATE_LIMIT_MAIL` row now say that an announcement emailed to guests counts once, however many guests it reaches. Ticket 01 had written that the limit counts only account emails.

Decisions and things to know:
- **The rate limit counts an announcement only when it emails someone.** `RATE_LIMIT_MAIL` is there to stop the instance flooding inboxes (`rate-limit/config.ts`), and one that reaches no guest, or is posted without mail, sends nothing. This also keeps the cap testable: the browser test posts eleven announcements from one address, against the dev and test profiles' `RATE_LIMIT_MAIL=5/1m`. If the maintainer wants every post counted, it is one condition in `postAnnouncementAction`, but the eleventh-announcement test would then have to change its client address part way through.
- **Without mail** the three boxes are shown checked as the default and disabled. Disabled boxes post nothing, so the action stores the default audience (Going, Maybe) to satisfy the column and the parser. The list then leaves out the "Sent to …" line, because nothing was sent; the no-mail line at the top of the page says why.
- **Drafts and cancelled events can have announcements.** The ticket sets no state rule. A draft has no guests, so nothing is emailed, and its announcements show to the host on the draft preview and to everyone once published. The spec's "Drafts have none" is met for guests, who see only the not-ready page.
- **The page shows every announcement to every viewer**; the audience decides only who is emailed. The explainer says so to the host.
- **Times** on both pages are in the event's zone, formatted in the viewer's locale with `formatMoment` ("Oct 7, 2:46 PM"), so every time on the page belongs to one clock, as on the guest list. The When tile shares that clock.
- **"Sent to …"** uses `Intl.ListFormat` through next-intl: "Going and Maybe", "Going, Maybe, and Can’t go"; 发送对象：参加和待定 / 寄送對象：參加和待定.
- The textarea has `maxLength` 2000 and `required`; the server checks both anyway.
- The success message names how many guests were emailed. When none of the picked guests gave an email, the host is told so.
