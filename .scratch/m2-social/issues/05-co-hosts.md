# 05: Co-hosts

**What to build:** A host makes a co-host link; whoever accepts it while signed in shares management of the event. Co-hosts can do everything but delete the event or manage co-hosts. The page names every host.

**Blocked by:** 01 The host is emailed when a guest replies (for `eventHosts`)

**Status:** done

- [x] Schema: `event_host` (`event_id` cascade, `host_id` cascade on user delete, `added_at`; primary key on both). `co_host_link` (id, `event_id` cascade, `token_hash` unique, `created_at`, `expires_at`, `used_at`, `used_by_id` null, `revoked_at`), modelled on `host_invitation`.
- [x] `src/hosts/`: `role.ts` with `type Role = "owner" | "coHost"` and `can(role, action)` for the actions `edit`, `publish`, `cancel`, `design`, `questions`, `guests`, `announcements`, `comments`, `share`, `resetLink`, `duplicate`, `delete`, `manageCoHosts`; owner can do all, co-host all but the last two. Pure, unit tested. `repository.ts` for memberships and links. `co-host-link.ts` for the token (random, hashed like the host invitation's), seven-day expiry, single use.
- [x] One gate: `findHostEvent(hostId, id)` (and anything else that answers "this host's event") now answers for the owner and for co-hosts, returning the event with the caller's `role`. Every event action checks `can(role, action)`; delete and the co-host pages check for the owner. The proxy's `/events/` check (`src/proxy.ts`) uses the same gate.
- [x] `eventHosts(eventId)` (ticket 01) returns owner first, then co-hosts in order added. Notifications from tickets 01, 03, 04 and 06 reach them all.
- [x] `/events/[id]/hosts`, owner only, reached from the manage page's buttons row ("Hosts"): the hosts (owner marked, co-hosts with Remove and confirmation), pending links (made when, expires when, Revoke), and "Make a co-host link", which creates one, shows it once with Copy, and says it works for one person and expires in 7 days. At most ten co-hosts: the button is replaced by a sentence at the cap. A co-host opening this page sees only "Leave this event" with confirmation.
- [x] `/co-host/[token]`: a signed-in host who is not the owner and not already a co-host sees the event's title and "Accept" (a post); accepting makes them a co-host and opens the manage page. The owner sees "This is your own event." An existing co-host is sent to the manage page. A visitor who is not signed in is sent to sign in and back here afterwards; the sign-in page notes that a co-host link needs an account on this instance, and on an Invitation-only instance an account needs a host invitation from the operator. A used, revoked or expired link says so; a link that was never made is the not-found page (`src/proxy.ts`, as `/host-invitation/`). The link counts against the `signIn` rate limit in the proxy.
- [x] The event page shows "Hosted by {hosts}" with the hosts' display names as a list in the viewer's language (`Intl.ListFormat`, conjunction), owner first. The preview card is unchanged.
- [x] The dashboard lists co-hosted events in upcoming and past with a "Co-host" badge; the manage page shows the badge too and hides Delete and the Hosts button from co-hosts. The delete-account confirmation says events the host owns are deleted, co-hosted or not, and that they leave events they co-host.
- [x] Unit tests: `can`; the link's expiry and single use as pure checks (as `host-invitation.test.ts` does).
- [x] Browser tests (`e2e/co-hosts.spec.ts`): owner makes a link; a second host accepts it and sees the event on their dashboard with the badge; the co-host edits the title and the event page shows it and names both hosts; the co-host's manage page has no Delete and a direct POST of the delete action is refused; the co-host leaves and the event is gone from their dashboard; a revoked link says so; a link opened signed out goes through sign-in and back; the owner removes a co-host.

## Notes for the implementer

- `findHostEvent` is called in many places; change its return shape once and let the type checker find them. Keep the surface small: the role on the event object.
- `Intl.ListFormat` is available in Node 22 and every evergreen browser; next-intl's `useFormatter().list()` wraps it.
- Commit subject, e.g. `Co-hosts: a host shares an event's management through a co-host link`.
