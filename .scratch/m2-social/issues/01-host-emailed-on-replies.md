# 01: The host is emailed when a guest replies

**What to build:** Every host of an event gets an email when a guest replies for the first time, changes their status, or removes their RSVP, with a per-event switch to turn it off. This ticket also builds the mail outbox and the worker that every later email about an event goes through (spec, "Mail outbox and worker").

**Blocked by:** none

**Status:** done

- [x] Schema (one migration): `mail_outbox` (id, `event_id` uuid null, cascade on event delete; `to`, `subject`, `text`; `created_at`; `send_after` timestamptz; `attempts` integer default 0; `last_error` text null). `event.notify_on_rsvp` boolean not null default true, and the migration sets it **false** on every existing row (spec, story 141). `event.locale` text not null default `'en'`.
- [x] `src/mail/outbox.ts`: `queueMail(rows)` writes rows; `sendDue(now)` claims due rows with `SELECT … FOR UPDATE SKIP LOCKED` inside a transaction, sends each through `sendMail`, deletes a row that sent, and on failure writes `attempts + 1`, `last_error`, and the next `send_after` from the schedule 1, 5, 15, 60 minutes; after the fifth failure the row is deleted and one log line names the failure with the address reduced to `…@domain`. The schedule is a pure function `nextAttempt(attempts, now)` with unit tests (the four delays, and "give up" after five).
- [x] `src/mail/worker.ts`: `startMailWorker()` is called from `instrumentation.ts` after the start checks, only when mail is configured, and runs `sendDue` every 60 seconds; `kickMailWorker()` runs it at once and is called by every action that queues mail (through Next.js `after()`, so the action's response does not wait). Two runs never overlap in one process. Nothing starts under `next build`.
- [x] `src/events/hosts.ts` (or wherever fits the Events module): `eventHosts(eventId)` returns the event's hosts as `{ id, name, email }[]`; today that is the owner alone. Ticket 05 adds co-hosts to it; every notification in M2 calls it.
- [x] When an RSVP is saved for the first time, when its status changes (guest or host edit), or when it is removed (guest withdraw or host removal), and `notifyOnRsvp` is on and mail is configured, one email per host is queued: subject and body from a new `Mail.rsvpReply` group, in the language of `event.locale`, naming the guest, their status, their plus-ones, and the guest list link `${baseUrl()}/events/<id>/guests`. Edits that keep the status queue nothing.
- [x] The event form's settings gain "Email me when a guest replies" (`notifyOnRsvp`), saved with the event. Saving the event form also stores the current locale in `event.locale`.
- [x] Unit tests: `nextAttempt`; the rule for which RSVP saves notify (first reply, status change, removal; not a details-only edit) as a pure function over before and after.
- [x] Browser test (`e2e/notifications.spec.ts`): a guest replies Going and the host's inbox in Mailpit gets one mail naming the guest and Going within 30 seconds; the guest changes to Maybe and a second arrives; the guest edits only their name and no third arrives; the host turns the setting off, a new guest replies, and nothing arrives.
- [x] `docs/operator/configuration.md`, Mail section: the list of what mail does gains "the host is emailed when a guest replies, unless they turn it off for the event", and a sentence that the app sends event mail from a queue inside the app container, retrying a failed message a few times.

## Notes for the implementer

- `instrumentation.ts` already imports modules lazily inside `register()`; do the same for the worker, and guard it with `process.env.NEXT_RUNTIME === "nodejs"` as the rest is.
- `after()` is in `next/server`; read `node_modules/next/dist/docs/` for it before using it.
- `sendMail` in `src/mail/send.ts` creates a transport per call; keep that for now, the worker sends a few at a time.
- The locale to store: `getLocale()` from `next-intl/server` in the save action.
- Commit subject in the repository's style, e.g. `Mail: the host is emailed when a guest replies, from a queue inside the app`.

How it landed:
- **Schema** (`drizzle/0014_mail_outbox_and_reply_notifications.sql`): `mail_outbox` as the ticket lists it, with `send_after` defaulting to `now()` and an index on `event_id` like every other event foreign key. `event.notify_on_rsvp` (default true) and `event.locale` (default `'en'`, typed as `Locale` in `schema.ts`). The generated SQL is hand-edited with `UPDATE "event" SET "notify_on_rsvp" = false` after the column is added; on the dev database all 7,730 existing events read false after it ran.
- **`src/mail/retry.ts`**: `nextAttempt(attempts, now)`, where `attempts` counts the failure just now: 1, 5, 15, 60 minutes, then `null`.
- **`src/mail/outbox.ts`**: `queueMail(rows)` (rows are `{ eventId, to, subject, text }`, written whole at queue time) and `sendDue(now)`. `sendDue` claims **one** due row per transaction (`ORDER BY send_after, id LIMIT 1 FOR UPDATE SKIP LOCKED`) and loops until none is due, so a crash mid-run resends at most one message, and mail goes out in the order it was queued. A row that sent is deleted; a failure writes `attempts + 1`, `last_error` and `send_after`; the fifth failure deletes the row and logs `Mail: gave up on a message to …@domain after 5 attempts: <error>`, with the full address also replaced in the error text.
- **`src/mail/worker.ts`**: `startMailWorker()` (no-op under `PHASE_PRODUCTION_BUILD` or without mail) sets a 60-second interval; `kickMailWorker()` runs `sendDue(new Date())`. State (`timer`, `running`, `again`) lives on `globalThis[Symbol.for("openinvites.mailWorker")]`, as the rate limits' does, because the instrumentation bundle and the action bundles have their own module instances. A run asked for during a run sets `again`, and the running one loops once more. Errors are caught and logged; the next minute retries. `register()` calls it last, after the operator promotion.
- **`src/events/hosts.ts`**: `eventHosts(eventId)`: one select of `user` joined from `event` on `host_id`. Ticket 05 changes that query.
- **`src/rsvps/notice.ts`**: `rsvpNotice(before, after)` over statuses (null for no RSVP) returns `"replied" | "changed" | "removed" | null`.
- **`src/rsvps/notify-hosts.ts`**: `notifyHostsOfRsvp(event, previous, current)` never throws (since `00aaeab`: it catches and logs `Mail: could not queue the hosts' email about an RSVP to event <id>`), applies the rule, checks `event.notifyOnRsvp` and `isMailConfigured()`, builds the subject and body with `getTranslations({ locale: event.locale, namespace: "Mail.rsvpReply" })`, queues one row per host, and calls `after(kickMailWorker)`. Called from all four actions in `src/rsvps/actions.ts`; in the two guest actions, only after the device's cookie is set or deleted. `editRsvpAsHost` now returns the RSVP as it was (read `FOR UPDATE` in the same transaction as the write) and `deleteRsvp` returns the row it removed, so the actions know the status before.
- **`src/locale/request.ts`**: the request config now honours the locale a caller names (`getTranslations({ locale })`); before, it always answered with the visitor's cookie or Accept-Language locale, so an explicit locale was ignored. Calls without a locale behave as before.
- **Event form**: "Email me when a guest replies" (`notifyOnRsvp`) after "Who can see the guest list", checked by default for a new event. Both save actions write `locale: await getLocale()` (`EventChanges = EventInput & { locale }` in `events/repository.ts`).
- **`Mail.rsvpReply`**: `subject.{replied,changed,removed}`, `body.{replied,changed,removed}`, `status.{going,maybe,cant}`. For example, subject "Priya Nair replied to Ada’s birthday: Going", body "Priya Nair replied to Ada’s birthday: Going, bringing one more person." then "Your guest list:" and the link, then one line on how to turn these emails off. A removal reads the same whoever removed the RSVP, guest or host: "Priya Nair’s RSVP to Ada’s birthday was removed. It said Going." Decisions and things to know:
- **The browser test checks "nothing arrives" against a later email.** After the name-only edit and the second guest's reply with emails off, the host turns emails back on and the second guest changes to Can't go. The test waits for that email, then expects exactly four emails in the inbox (verification plus three). Because the outbox sends in queue order, anything the two silent saves had queued would arrive first. Mutation checks: with `event.notifyOnRsvp` ignored, and with `rsvpNotice` returning "changed" for an unchanged status, the test fails with "Expected: 4, Received: 5". Waits after RSVP and form saves are 15 seconds, as other specs use for real work.
- `e2e/events.ts` `createPublished` now also returns the host's `email`.
- **Retry timing is tick-bound.** `send_after` is the run's `now` plus the delay, and the next tick comes about 60 seconds after this one, so a 1-minute retry can just miss it by milliseconds and go a minute later. Seen by hand: 03:58:01.172 was due, and the 03:59:01.157 tick skipped it.
- **A hung SMTP connection holds the run.** Each send holds its transaction open. Under `next dev`, `smtp://127.0.0.1:1` left the connection in SYN-SENT (WSL drops it rather than refusing it), so `sendMail` waited for nodemailer's two-minute connection timeout. Runs don't overlap, so the next tick just sets `again`.
- A host who edits a guest's status on their own guest list gets the email too, as the ticket asks.
- The setting shows even on an instance without mail. Hiding it would post `notifyOnRsvp` off and quietly switch events off.
- "Nothing starts under `next build`": Next.js itself skips `register()` during the build (`registerInstrumentation` returns under `phase-production-build`), and `startMailWorker` checks the phase too. `pnpm build` with no `DATABASE_URL` set succeeded, so `register()` (whose migrations would throw without it) never ran.
