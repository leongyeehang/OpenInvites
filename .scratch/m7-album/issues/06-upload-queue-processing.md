# 06: Videos: the upload protocol, the queue and the processing

**What to build:** One way to add anything to an album: ask, send the parts, finish. Photos take it too, so one file is in memory at a time. A finished video is stored as sent, queued, and processed by ffmpeg in the app container: probed, rewrapped at original quality with its metadata dropped, given a lighter copy when it needs one, a poster and a thumbnail. Items in processing or failed are kept in their states, and the hosts are emailed when a video waits for approval. The largest ticket: commit it in steps.

**Blocked by:** 05 Videos: ffmpeg in the image, the video schema, and the event's video settings

**Status:** ready-for-agent

### The queue

- [ ] `src/album/jobs.ts` (pure parts in `jobs.test.ts`): `LEASE_MS = 60 * 60 * 1000`, `MAX_TRIES = 3`; `claimable(job: { leasedAt: Date | null }, now: Date): boolean`; `exhausted(job: { attempts: number }): boolean`; `claimJob(me: string, now: Date): Promise<ClaimedJob | undefined>` as one statement, `update video_job set leased_at = now, leased_by = me, attempts = attempts + 1 where id = (select id from video_job where leased_at is null or leased_at < now - lease order by created_at limit 1 for update skip locked) returning *` (a committed lease, never a transaction held across ffmpeg); `completeJob(photoId, result: { width; height; durationMs; codec; copy: VideoQuality | null })`: one transaction that locks the event row, decides the status by `photoStatusFor` from the row's owner (a host's at once approved, a guest's pending under approval), and runs `update photo set … where id = $id and status = 'processing' returning id`; no row back means the item was deleted meanwhile, and the caller removes what it stored **(plan ruling 20)**; the job is deleted either way; `failJob(photoId, error: string)`: when `exhausted`, the item becomes `failed` and the job goes, else the lease is cleared and `last_error` kept.

### The processing

- [ ] `src/album/processing.ts`, each ffmpeg call through `spawn("nice", ["-n", "10", "ffmpeg", …, "-threads", "2"])` with a timeout and stderr kept for the error: `probe(path): Promise<Probe>` from `ffprobe -v error -print_format json -show_format -show_streams` → `{ codec: string; codecString: string; width: number; height: number; rotation: number; durationMs: number; bitRate: number; hasAudio: boolean }` (the RFC 6381 string for the player's `canPlayType`, built from the stream's `codec_name`, `profile` and `level`, with `avc1.42E01E` and `hvc1.1.6.L93.B0` as fallbacks); `rewrap(input, output, probe)`: `-map 0:v:0 -map 0:a:0? -c copy -map_metadata -1 -map_metadata:s:v -1 -map_metadata:s:a -1 -map_chapters -1 -movflags +faststart -f mp4`, with `-tag:v hvc1` for HEVC, and a second try with `-c:a aac -b:a 128k` when the copy fails (audio MP4 cannot hold); `makeCopy(input, output, quality)`: `-c:v libx264 -preset veryfast -crf 23 -maxrate {6M|3M} -bufsize {12M|6M} -vf "scale=w='if(lt(iw,ih),T,-2)':h='if(lt(iw,ih),-2,T)'"` with `T` 1080 or 720 (the short side), `-pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart -map_metadata -1`; `posterFrame(input, atMs)`: `-ss {s} -i input -frames:v 1 -f image2 frame.png` (`-ss 0` under a second), then sharp exactly as `src/album/files.ts:47-50` makes the large and thumb files (the poster up to 2048 inside, the thumb 480 cover).

## Notes for the implementer

- Hold no database transaction across an ffmpeg run: the lease is committed, the work runs, and the result is written in a short transaction.
- Until ticket 07 teaches the page about video items, `albumFor` (`src/app/e/[slug]/page.tsx:130-155`) leaves `kind = 'video'` rows out of what it shows, so a video in processing never reaches a component that expects a photo.
- Headless Chrome has no HEVC decoder; nothing in this ticket plays a video in the browser, which is ticket 07's.
- The temp directories are per container; the deploy docs (ticket 11) say the site runs one app container and that `/tmp` needs about three times the largest video free.
- Commit in steps, e.g. `Album: one upload protocol for photos, in parts` → `Videos: a finished upload is stored as sent and queued` → `Videos: the queue processes a clip with ffmpeg` → `Videos: the hosts are emailed when a video waits`.
